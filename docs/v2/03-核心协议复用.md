## 1. 基础设施：CookieJar 与 ProtocolClient

### 1.1 CookieJar（protocol-login.mjs:76-152）

手写 cookie 管理（不依赖第三方库）：`setFromResponse(url, headers)`（解析 set-cookie，含 `parseSetCookie` 1714-1745 与域名/路径/secure 匹配 `cookieMatches` 1747-1754）、`headerFor(url)` 拼请求头、`merge(cookies)` 合并 Python 侧回传的 cookie、`toJSON()/fromJSON()` 序列化（checkpoint 用）。

**双层 cookie 存储**：JS 侧 CookieJar + Python curl cookie jar 并存，每次响应通过 `transportCookies` 合并回 JS 侧（protocol-login.mjs:222-223）。这是刻意设计（curl 层处理连接级 cookie，JS 层做流程判断），复用时保持。

### 1.2 ProtocolClient（protocol-login.mjs:154-277）

所有协议请求经过 `request(method, url, options)`，返回 `{ res, text, location, url }`：

- 注入浏览器头（`browserHeadersForTransport` 62-74）：user-agent / accept-language / sec-ch-ua*。**TLS transport 启用时不发 sec-ch-ua 头**（curl_cffi 自带）。
- **关键**：非 GET 且目标是 `auth.openai.com` 或路径以 `/api/accounts/` 开头时，自动附加：
  ```
  x-access-flow-invocation-id: <randomUUID>       (每次请求新生成)
  sec-fetch-site: same-origin
  sec-fetch-mode: cors
  sec-fetch-dest: empty
  priority: u=1, i
  ```
  （protocol-login.mjs:184-194）
- `redirect: "manual"` + AbortController 超时，重定向由 `follow()`（249-266）手动跟随，**最多 12 跳**，中途命中本地回调（localhost `/auth/callback`）即停。
- 响应级风控检测（`isRiskControlResponse` 1695-1704）命中则抛 `PROXY_RISK_CONTROL`。

## 4. Sentinel 反检测（sentinel.mjs）

**唯一耦合点**：仅 Step 4 新账号 about-you 建档时调用（flow=`oauth_create_account`），token 作为 `openai-sentinel-token` 请求头随 `create_account` 发送。普通登录/OTP/MFA/token 交换不触发。

导出：`defaultSentinelEnv`、`fetchSentinelToken(options)`、`resolveSentinelDeviceProfile`（1497-1501）。

```
fetchSentinelToken({
  deviceProfile,          // 来自 tls-transport 的 browserIdentityForTlsProfile，与 TLS 层同一身份
  userAgent, sendClientHints,   // TLS transport 开启时 sendClientHints=false
  fetch,                  // 注入 client.rawFetch
  reqEndpoint,            // auth.openai.com 场景固定 https://sentinel.openai.com/backend-api/sentinel/req
  deviceID,               // oai-did cookie
  flow                    // "oauth_create_account"
}) → Promise<string>      // JSON 字符串
```

内部三步：

1. **requirements token（前置 PoW）**：随机 seed 做 FNV-1a 变种哈希搜索（`sentinelHashHex` 1443-1455），难度恒为 `"0"`，产出 `gAAAAAC<base64>~S`。指纹数据数组 25 项（`collectFingerprintData` 359-387）：屏幕宽高和、日期串、`jsHeapSizeLimit`、UA、脚本 src、buildHash、语言、`documentKeys/windowKeys` 随机键、硬件并发数、`timeOrigin`、`ai/solana/InstallTrigger in window` 探测位等。
2. **requirements 请求**：`POST {reqEndpoint}`，headers `content-type: text/plain;charset=UTF-8`、`origin: https://sentinel.openai.com`、`referer: .../sentinel/frame.html?sv=20260219f9f6` + 浏览器头；body `{p, id, flow}`。响应含 `proofofwork`、`turnstile.dx`、`token`。
3. **enforcement PoW**（`getEnforcementToken` 324-340）：若 `requirements.proofofwork.required` 且有 seed/difficulty，最多 50 万次迭代做十六进制前缀碰撞，产出 `gAAAAAB...`；每 5000 次让出事件循环。
4. **Turnstile DX**（`computeTurnstileDx` 398-438）：`requirements.turnstile.dx` 是 base64+XOR 加密的字节码程序。首选**官方 SDK 离线运行**（`loadSdkTurnstileRunner` 444-585）：读 `sentinel-sdk.js` 源码，字符串补丁注入 `t.__codexTurnstileDx=function(requirements,key,dx){...}`（450-455），在 `node:vm` 沙箱（伪造 window/navigator/document/localStorage/location/performance/crypto）执行取回 DX token；兜底**自研 TurnstileVM**（586-1046，opcode 0~35 解释器，500ms 超时）。

最终 token：JSON 字符串 `{"p":<PoW证明>,"t":<DX token 或 null>,"c":requirements.token,"id":deviceID,"flow":flow}`。

**脆弱点**：SDK 补丁锚点是精确字符串匹配，sentinel SDK 升级即失效（自动回退自研 VM，但新 opcode 支持有限）。维护时先跑 `test/protocol-smoke.mjs`。

## 5. TLS 指纹传输（tls-transport.mjs / tls_transport.py）

### 5.1 架构

JS 侧 spawn Python 子进程运行 `tls_transport.py`，stdin/stdout NDJSON 行协议通信。Python 用 `curl_cffi==0.15.0`（底层 curl-impersonate），`impersonate="chrome146"` 等参数模拟 Chrome ClientHello（JA3）与 HTTP/2 指纹。

Python 解释器发现：`TOSUB2_PYTHON` env > Windows `python`/`py -3` > `python3`/`python`，用 `import curl_cffi` 探测（372-387）。

启用条件：目标是 chatgpt.com / auth.openai.com 域且未传 `--native-http`（361-370）。

### 5.2 NDJSON 协议

请求（JS → Python）：`{"id":"<uuid>","operation":"configure|probe_profiles|request",...}`；响应：`{"id":"...","ok":true,"result":{...}}` 或 `{"ok":false,"error":"..."}`。每请求超时 = timeoutMs + 5s。

- `configure`：`{proxy: "http://...或null", impersonate: "chrome146"}` → 建 `curl_cffi.requests.Session`。profile 不受支持时按 `chrome146→chrome145→chrome142→chrome136` 降级。
- `probe_profiles`：枚举全部 `chromeNN` 按版本降序、4 并发探测（无代理直连场景选可用指纹，总超时 300s）。
- `request`：`{method,url,headers,body,timeoutMs}`，`allow_redirects=False`（重定向由 JS 侧手动跟随）。返回 `{status, headers:[[k,v]], body:base64, cookies:[...]}`。

⚠️ **注意**：响应 body 一律按 UTF-8 解码（tls-transport.mjs:220），二进制响应会损坏——复用时保持此限制即可（OpenAI 流程全是文本）。

### 5.3 代理预检与会话轮换

- `prepareProxy(proxyTemplate, validationUrl)`（89-160）：先真实访问 `chatgptBase + "/"` 验证代理出口能过 Cloudflare。
- 会话轮换（`rotateProxySession` 397-410）：用户名含 `-sid-XXXX-t-20` 或密码含 Kookeey 格式 `-JP-12345678-20m` 的代理，每次轮换替换会话号（`proxySupportsSessionRotation` 412-421 判定）。轮换消耗 `remainingProxySessionAttempts` 额度。
- `resetSession()`：重建 curl session（换 TLS 会话 + 清 Python cookie，JS CookieJar 不动）。

### 5.4 风控重试契约（对 v2 任务引擎最重要）

两个字符串错误码是子进程与外层的**信号契约**（protocol-login.mjs:2042-2044）：

| 信号 | 含义 | 外层（任务引擎）动作 |
|---|---|---|
| `PROXY_RISK_CONTROL` | 命中 Cloudflare/风控页（`cf-mitigated: challenge` 头、403+html、400/409+html+`Just a moment/cdn-cgi/challenge-platform/cf-challenge`） | 同代理原地重试 ≤3 次（间隔 1s）→ 仍失败则杀进程换会话重启 |
| `PROXY_CONNECTION_RETRY` | 代理连接类错误（timeout/proxyerror/curl 5/6/7/28/35...） | 换代理会话重启；连续 20 次失败终止（指数退避 1s→15s） |

顶层输出标记：`[proxy-risk-retry]`（2034-2035）与 `[proxy-session-attempt] <uuid>`（会话计数）。v2 中这些标记改为结构化事件（见 §8），语义不变：**最多 10 个有响应的代理会话**（连接失败不占额度）。

## 7. Outlook 邮件协议（outlook-mail.mjs）

### 7.1 取件接口

直接使用微软官方接口，固定端点，不使用第三方取件地址：

```http
POST https://login.microsoftonline.com/consumers/oauth2/v2.0/token
Content-Type: application/x-www-form-urlencoded

grant_type=refresh_token&client_id=<clientId>&refresh_token=<refreshToken>&scope=<URL编码后的scope>

GET https://outlook.office.com/api/v2.0/me/messages?$top=10&$orderby=ReceivedDateTime%20desc&$select=Id,Subject,From,ReceivedDateTime,BodyPreview,Body,IsRead
Authorization: Bearer <access_token>
Prefer: outlook.body-content-type=html
```

`scope` 使用 `https://outlook.office.com/IMAP.AccessAsUser.All https://outlook.office.com/Mail.ReadWrite offline_access`，与参考取件项目的邮箱授权一致。邮箱密码不发送；登录收码 `$top=5`，备用池默认 `$top=10`，最大 50。授权和读取共用 60 秒超时，不跟随重定向，不回退第三方。

从响应 `value` 数组读取邮件，将 Outlook REST 的 PascalCase 字段映射为现有 camelCase 结构。授权失败、非 JSON 或缺失 `value` 会抛错，不能视为空邮箱；错误不包含原始响应正文或令牌。

### 7.2 初始化关键字（备用号池导入用）

- **初始余额**（`extractBalanceFromMessages` 296-309）：subject/bodyPreview/body 拍平去 HTML，按时间倒序匹配正则 `/we[\s']*ve\s+added\s+([\d,]+(?:\.\d+)?)\s+credits\b/i`，**balance = credits / 25**，取最近一封。
- **封禁判定**（`isAccountBannedFromMessages` 312-329）：`BANNED_KEYWORDS` 命中 `account_deactivated` / `account has been deactivated` / `suspended` / `disabled` / `permanently deleted` / `your account has been banned` 等变体 → `{banned: true, reason: "邮件命中封禁关键词"}`。

### 7.3 登录期 OTP 轮询

- 进入邮箱验证码步骤前先记录收件箱基准（旧验证码指纹 + 时间）。
- 轮询只接受**基准时间之后到达**且发件人属于 `openai.com / tm.openai.com / email.openai.com / chatgpt.com / codex.chatgpt.com` 的邮件；验证码 + 邮件标识双去重；间隔 2.5s，最长 10 分钟。

## 8. json-events 事件协议规范（v2 新增改造）

### 8.1 改造原则

`protocol-login.mjs` 新增 `--json-events` 启动参数：

- **stdout 只输出 NDJSON 事件**（一行一个 JSON 对象，UTF-8，无其他杂音）；人类可读日志全部转 stderr（仍写任务日志文件）。
- **人工输入改从 stdin 读 JSON 行**（`{"action":"input","value":"..."}`）。
- 不带 `--json-events` 时**完全保持 v1 交互行为**（CLI 问答），改造通过在现有 prompt/输入点插入条件分支实现，不移动协议流程代码。

### 8.2 事件类型全集

所有事件共通字段：`{"type":"<类型>","ts":"<ISO8601>","attempt":"<attempt>"}`（attempt=含代理重启在内的尝试序号，从 1 起）。

| type | 触发时机 | 附加字段 | 服务端处理 |
|---|---|---|---|
| `starting` | 子进程完成参数解析、即将开始 | `mode: "full"\|"refresh"\|"totp_setup"`，`email` | job: queued→running |
| `stage` | 阶段切换 | `stage`: `web_login\|email_otp\|password\|mfa_otp\|totp_setup_otp\|about_you\|add_phone\|phone_otp\|oauth\|workspace\|finalizing\|refreshing` | 更新 job.stage |
| `input_required` | 流程等待人工输入 | `kind`: `password\|email_otp\|mfa_otp\|totp_setup_otp\|phone\|phone_otp`；`detail`: 提示文案；`can_resend`: bool | job: running→awaiting_input, prompt_kind=kind |
| `input_accepted` | 收到合法输入 | `kind` | job: awaiting_input→running |
| `log` | 人类可读日志同时镜像一条 | `level`: `info\|warn\|error`，`message`（已脱敏） | 仅落日志文件，不驱动状态 |
| `proxy_session_attempt` | 代理换会话 | `n`: 第几个会话，`session_id` | 计数 proxy_attempts |
| `risk_retry` | 风控原地重试 | `reason`: `PROXY_RISK_CONTROL\|PROXY_CONNECTION_RETRY`，`retry_in_ms` | 记录；服务端自己决策杀进程重启（子进程自身也会重启内部流程，见 §5.4） |
| `checkpoint_saved` | 断点保存 | `stage`, `path` | 记录 checkpoint_path |
| `resume_used` | 从断点续跑 | `stage` | 记录 |
| `balance` | （可选）流程内查到余额 | `value` | 回填 accounts.balance |
| `totp_secret` | setup-totp 模式产出密钥 | `secret`（仅此事件携带，不进日志） | 解密入库 credentials_enc.totp_secret |
| `result_saved` | 导出文件写盘成功 | `path`, `account`: `{email, name, chatgpt_account_id}` | 置 result_path；解析入 tokens_enc |
| `error` | 致命错误，进程即将退出 | `code`: 见 §9，`message`，`fatal`: true，`retry_proxy`: bool（是否值得换代理重试） | job→failed；retry_proxy=true 时引擎决定是否自动重启 |
| `exit` | 正常结束前最后一条 | `ok`: true | job→completed（或 refresh 回退场景由服务端决策） |

示例流（email_otp 登录 + 绑手机）：

```
{"type":"starting","ts":"...","attempt":1,"mode":"full","email":"a@b.com"}
{"type":"stage","ts":"...","attempt":1,"stage":"web_login"}
{"type":"proxy_session_attempt","ts":"...","attempt":1,"n":2,"session_id":"9f3c..."}
{"type":"stage","ts":"...","attempt":1,"stage":"email_otp"}
{"type":"input_required","ts":"...","attempt":1,"kind":"email_otp","detail":"请输入邮箱验证码","can_resend":true}
{"type":"input_accepted","ts":"...","attempt":1,"kind":"email_otp"}
{"type":"stage","ts":"...","attempt":1,"stage":"oauth"}
{"type":"stage","ts":"...","attempt":1,"stage":"add_phone"}
{"type":"input_required","ts":"...","attempt":1,"kind":"phone","detail":"请输入手机号","can_resend":false}
{"type":"checkpoint_saved","ts":"...","attempt":1,"stage":"phone_otp","path":"..."}
{"type":"result_saved","ts":"...","attempt":1,"path":"data/results/<job>.json","account":{"email":"a@b.com","name":"oauth---a@b.com","chatgpt_account_id":"us_..."}}
{"type":"exit","ts":"...","attempt":1,"ok":true}
```

### 8.3 stdin 输入协议

`awaiting_input` 期间服务端可写以下 JSON 行（换行结尾）：

```jsonc
{"action":"input","value":"123456"}     // 提交当前输入（验证码/密码/手机号）
{"action":"resend"}                     // 重发验证码（can_resend=true 时）
{"action":"change_phone","value":"+8613800000000"}  // 换手机号
{"action":"quit"}                       // 放弃，子进程走清理后以非零码退出
```

非法 JSON / 非法 action：stderr 记录并忽略，不崩溃。

### 8.4 自动化输入源（服务端侧）

`input_required(kind=email_otp)` 时任务引擎按账号凭据自动作答，来源优先级：

1. `credentials.outlook` 存在 → Outlook 取件轮询（§7.3）自动收码。
2. `credentials.mail_api_url` 存在 → 泛化收码 API（mail-otp.mjs）。
3. 都没有 → 停在 awaiting_input 等前端人工提交（`POST /api/v1/jobs/{id}/input`）。

`kind=phone/phone_otp`：接码平台（sms-providers）自动取号收码，或人工。`kind=password`：`credentials.password`，无则人工。`kind=mfa_otp`：`credentials.totp_secret` 本地生成，无则人工。

## 9. 错误码全集（`error` 事件 code）

| code | 判定来源（v1 行号） | retry_proxy | 服务端动作 |
|---|---|---|---|
| `PROXY_RISK_CONTROL` | isRiskControlResponse 1695-1704 | true | 换会话重启（≤10 会话） |
| `PROXY_CONNECTION_RETRY` | 连接类错误 463-472 | true | 换会话重启（连续 20 次封顶） |
| `REFRESH_TOKEN_INVALID` | refresh 模式 1502-1543 | false | 自动转完整登录 job |
| `UNEXPECTED_LOGIN_PAGE` | 750 | true(一次) | 新登录重试一次后失败 |
| `SESSION_SELECTION_INVALID` | 1114 | false | 标记 needs_reauth，可手动重登 |
| `PROFILE_SECURITY_CHECK_REQUIRED` | create_account 含 `registration_disallowed`（957-961） | false | 账号标记风险，**不自动重试** |
| `ACCOUNT_PROFILE_REQUIRED` | 905 | false | 同上 |
| `MFA_OTP_INVALID` / `EMAIL_OTP_INVALID` / `PASSWORD_INVALID` | 809 / 1575-1579 / 847 | false | 留在 awaiting_input 或 failed，人工处理 |
| `OTP_RESEND_LIMITED` | resend 429（1590） | false | failed，提示稍后再试 |
| `CHECKPOINT_INVALID` / `SESSION_EXPIRED` | 1828-1832 | true(一次) | 清断点完整重登一次 |
| `ADD_PHONE_FAILED` | 手机号不可用等 | false | 回 awaiting_input 换号 |
| `INTERNAL` | 兜底 | false | failed + 日志 |

**永久性账号失败**（对应 v1 `isPermanentAccountFailure` 3537-3540 的语义）：`account_deactivated / account_deleted / account_suspended` 等出现在错误信息中 → 账号置 `auto_repair_blocked=1`，监控永不自动修复，提示人工确认（通常应废弃）。

## 11. 已知脆弱点与维护守则

1. **sentinel-sdk.js 补丁锚点**精确字符串匹配（sentinel.mjs:450-455），SDK 升级即失效 → 回退自研 VM。升级 SDK URL 时必须同步验证补丁锚点，跑 `test/protocol-smoke.mjs`。
2. **HTML 抓取**：choose-an-account 页抽 `us_` session_id（5 种正则兜底 1618-1628）、页面 pathname 判断（859-912）——auth.openai.com 改版敏感。改版时优先更新 `extractFirstSessionId` 正则族。
3. **OAuth code 一次性**：交换失败只能整个授权重跑；checkpoint（阶段 `email_verified → phone_required → phone_otp → oauth_continue → callback_ready`，1767-1783）是对冲手段，文件权限 0600。
4. **token 交换直接走 transport.fetch**（1402），新增请求头时注意别破坏其手动组头逻辑。
5. 上游任何改版，先在 CLI 模式（不带 --json-events）人工验证流程，再确认 json-events 模式无回归。
