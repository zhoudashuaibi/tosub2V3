# 06-02 页面详细设计

通用组件规范先行，然后逐页描述。所有表格基于 `data-table` 封装（TanStack Table：行多选 checkbox、服务端分页、列排序白名单、工具栏筛选、选中后底部浮出 `batch-action-bar`）。

## 0. 通用组件

### StatusBadge（统一状态→样式映射）

| 域 | 值 → 颜色/文案 |
|---|---|
| 任务 | queued=灰「排队」 running=蓝「进行中」 awaiting_input=琥珀「待输入」 completed=绿「已完成」 failed=红「失败」 canceled=灰「已取消」 |
| 主池账号 | active=绿「可用」 authorizing=蓝「授权中」 needs_reauth=琥珀「待重新授权」 |
| 备池账号 | mail_pending=灰「待初始化」 mail_failed=红「初始化失败」 joining=蓝「加入中」 |
| 废池原因 | banned_401=红「封禁(401)」 rate_limited_429=琥珀「限流(429)」 repair_failed=琥珀「修复失败」 login_failed=红「登录封禁」 manual=灰「手动废弃」 |
| 代理 | alive=绿「可用」 dead=红「失效」 cf_challenge=琥珀「被CF拦截」 unknown=灰「未测」 testing=蓝「测试中」 |
| 封禁标记 | banned=1 → 红色「已封禁」徽章（叠加油漆刷 tooltip 显示 banned_reason） |

### BalanceTag：`$4.96`（绿）/ `$0.00`（灰）/「未查询」（灰字）。余额列可排序。

### ImportDialog：多行 textarea（等宽字体，占位示例格式）+「导入」按钮 → 响应结果分区展示（成功 N 条 / 各类重复 / 非法行），重复区文案见 §2.1。

### ConfirmDialog：危险操作二次确认（删除/废弃/取消全部），红色按钮。

## 1. 登录页 `/login`

- 居中卡片（shadcn Card，宽 380px），标题「toSub2 控制台」。
- 两种模式由 `GET /auth/session` 的 `password_initialized` 决定：
  - 正常登录：单字段「访问密码」password input + 提交按钮；错误信息行内显示（含剩余次数/锁定倒计时）。
  - 首次设置（`?setup=1`）：字段「设置访问密码」+「确认密码」，提示「部署在公网，请设置强密码」。
- 成功 → 跳转 `/`。

## 2. 备用号池 `/pools/reserve`

**页头**：标题 + 统计徽章（总数 / 可用 / 已封禁 / 加入中）+ 主操作按钮。

**工具栏**：搜索框（邮箱模糊）、状态筛选（下拉）、主按钮「导入账号」。（批量重拉邮件入口在下方批量操作条，非工具栏）

**表格列**：

| 列 | 说明 |
|---|---|
| ☑ | 行选择（全选/清空） |
| 邮箱 | 主列，加锁图标表示已封禁（tooltip 原因） |
| 初始余额 | BalanceTag（initial_balance） |
| 封禁状态 | 已封禁徽章 / 「—」 |
| 邮件状态 | mail_status（ok=绿点、fetch_failed=红点+悬浮 mail_error、checking=旋转图标） |
| 导入时间 / 检查时间 | 相对时间（悬浮绝对时间） |
| 操作 | 「加入主号池」（单条）、「重新检查」（refresh-mail）、「删除」 |

**批量操作条**（选中 >0 浮出）：`已选 N 项` + **「批量加入主号池」** + 「导出账号」 + 「重新检查」（选中项批量重拉邮件，前端并发 10 分批调用单条 refresh-mail） + 「批量删除」。

### 2.1 导入弹窗（核心交互）

1. 单一输入框（textarea + 选择文件），导入 **sub2api 账号导出 JSON**：`accounts[].notes` 携带邮箱四段（`mailbox.password` 为邮箱密码）、GPT 密码（`gpt.password`）、两步验证（`two_factor.enabled + secret`）；`credentials` 里的 OAuth tokens 忽略，条目全部进备用号池，加入主号池走本系统登录授权。一次导入全部补全，不再分 2FA / 密码两个输入框。
2. 提交 → `POST /accounts/import` → 结果弹窗：
   - ✅ 成功导入 N 条（tosubV2 跨实例导出文件带 tokens 时才有「N 个账号直入主号池」）；
   - ⚠️ 主号池重复：**「e@b.com、f@b.com 账户已在主号池中」**（超过 5 个：「e@b.com 等 N 个账户已在主号池中」）；
   - ⚠️ 废弃池重复：「g@b.com 曾在废弃号池（限流429），重新导入？」→「仍然导入」按钮（带 `force_discard=true` 重提交）；
   - ⚠️ 远端 sub2api 重复：同理（`force_remote=true`）；
   - ❌ 非法行列表（行号 + 原因）。
3. 导入成功后 toast 提示「已开始邮件初始化，稍后刷新查看余额与状态」。

### 2.2 加入主号池交互

- 单条/批量点击 → 直接发 `POST /accounts/join-main`（封禁账号已在响应 skipped 中，toast 提示原因）。
- joining 状态行显示进度链接「查看任务」→ 跳任务中心（预筛该邮箱）。

## 3. 主号池 `/pools/main`

**页头**：统计徽章（可用 / 授权中 / 待重授 / 总余额 $ / 已上传 sub2api）。

**工具栏**：搜索、状态筛选、余额排序切换、「添加账号」（v1 兼容手动添加单账号弹窗：邮箱+密码/收码API/2FA 密钥/Outlook 四选多）。

**表格列**：

| 列 | 说明 |
|---|---|
| ☑ / 邮箱 | needs_reauth 时邮箱旁琥珀感叹号 |
| 状态 | StatusBadge（主池账号域） |
| 余额 | BalanceTag（balance + 悬浮 checked_at / balance_error） |
| 远端状态 | sub2api 上传后显示：绿点 active / 红点 error（悬浮 error_message，数据来自 remote-accounts 或上传回执）｜未上传显示「—」 |
| 上传时间 / 最近登录 | 相对时间 |
| 操作 | 「上传 sub2api」（单条）、「重新授权」、「查余额」、「废弃」、「删除」 |

**批量操作条**：`已选 N 项 · 合计余额 $xx.xx` + **「批量授权」** + **「批量上传 sub2api」** + **「批量获取余额」** + 「导出(sub2api格式)」+ 「导出(原始资料)」+「批量废弃」+「批量删除」。

### 3.1 上传配置弹窗（批量上传前弹出）

字段（默认值 = 服务端存储的 upload_defaults，本次可临时覆盖并可勾选「保存为默认」）：

- 分组多选（「读取配置」按钮拉 `GET /sub2api/groups`）；留空 = 后端默认分组。
- 并发数 / 负载因子 / 优先级（留空 = 保留账号原值）。
- 模型白名单（tags 输入，逗号分隔）。
- ☑ 自动选择绑定最少的代理（默认开；关闭后出现手动代理下拉，选项来自 `GET /sub2api/proxies`）。
- ☑ 禁用 5h 自动暂停　☑ 禁用 7d 自动暂停（两开关独立，默认关）。
- ☑ API 长上下文计费（默认开）。
- **Codex 指纹收敛**下拉：关闭（透传，默认）/ 仅设备 / 设备+会话 / 完全收敛，取默认值 = 服务端 `upload_defaults.codex_fingerprint_mode`，随本次上传按 `extra.codex_fingerprint_mode` 写入新增账号（与 sub2api 账号编辑页同款四档；off 不写键）。
- 未配置 sub2api（GET config 无 base_url）时弹窗变为「先去配置」引导按钮 → 跳 `/sub2api`。

上传结果 toast + 结果弹窗：新增 X、替换 Y、失败列表（邮箱+原因）。

## 4. 废弃号池 `/pools/discard`

**表格列**：☑ / 邮箱 / 废弃原因（StatusBadge 废池域）/ **代理 IP** / 详情（截断+悬浮全文 discard_detail）/ 加入备用池 / 加入主号池 / 初始余额 / 已用额度 / 废弃时间 / 操作「移回主号池」「彻底删除」。

- 「代理 IP」＝**废弃那一刻**的出口代理：主行代理名（sub2api 代理 name，纯数字编号），副行 `认证账号 <username>`；两行都可悬浮看代理 ID 与抓取时间，取不到时显示 `—`（老数据不反推成「直连」）。
- 值不是现查的：废弃时抓一次写快照列（`discard_proxy_name` / `discard_proxy_user` / `discard_proxy_id` / `discard_proxy_at`）。远端绑定会被一键换 IP 改绑、也会随号一起消失，事后查不到真实出口。
- 用途：同一个代理上死了一批号 = 该 IP 被拉黑的信号。搜索框（`q`）在废弃池同时匹配邮箱 / 代理名 / 认证账号，可直接按 IP 反查；表头可点「代理 IP」排序（空值沉底）。

**批量操作条**：「批量移回主号池」「批量彻底删除」。

页头提示条（灰）：「移回主号池后账号为待重新授权状态，建议先批量授权再上传。」

## 5. 任务中心 `/jobs`

**页头**：统计徽章（排队/进行中/待输入）+「取消全部」按钮（ConfirmDialog）。

**工具栏**：状态筛选 tab（全部/进行中/待输入/已完成/失败）、类型筛选、邮箱搜索。

**表格列**：邮箱 / 类型（登录·刷新·余额·2FA）/ 状态（StatusBadge+stage 中文）/ 尝试次数 / 代理（display_url）/ 开始时间 / 操作。

**行交互**：

- `awaiting_input`：行展开显示内联输入区（按 `prompt_kind` 渲染：验证码/密码/手机号 6 位输入框等），按钮「提交」「重发验证码」（can_resend）「放弃」。
- 展开行「日志」：LogViewer（2s 增量轮询，自动滚底，暂停滚动按钮）。
- 操作列：取消（活跃时）/ 重试（终态时）/ 下载产物（completed+has_result）。

stage → 中文映射表（web/src/lib/format.ts 维护）：`web_login=进入登录` `email_otp=邮箱验证码` `password=密码验证` `mfa_otp=两步验证` `about_you=补充资料` `add_phone=绑定手机` `phone_otp=短信验证码` `oauth=OAuth 授权` `finalizing=生成导入文件` `refreshing=刷新令牌`。

## 6. 代理列表 `/proxies`

**页头**：统计徽章（可用/失效/CF拦截/未测）+「批量导入」+「测试全部连通性」。

**表格列**：☑ / 代理（display_url 等宽字体）/ 备注 / 协议 / 状态（StatusBadge）/ 延迟（ms，dead 显示 —）/ 最近检测时间 / 失败计数（>0 红字，tooltip 说明）/ 操作「测试」「编辑备注」「删除」。

- 「测试全部」→ `POST /proxies/test`（无 ids）→ 行内状态变 testing（旋转）→ 逐条出结果；顶部进度条 `已测 x/y`（由列表轮询 stats 推算）。
- 导入弹窗：textarea 占位 `http://user:pass@host:port----备注（可选）`；结果同 §2.1 风格（created/duplicates/invalid_lines）；导入后提示「立即测试？」→ 确定 = 触发 test。

## 7. Sub2API 管理 `/sub2api`

分区卡片布局（上下两卡片）：

**卡片 A：连接配置**

- 后端地址 base_url 输入框。
- 管理员密钥：password input，已配置时占位符显示 `sk-****abcd`（保存时留空=不修改）。
- 「测试连接」→ `POST /sub2api/test` 显示 ✅ 连接正常（4 个分组，230ms）/ ❌ 错误。
- 「保存配置」。

**卡片 B：上传默认值**（同 §3.1 弹窗的字段集，这里是持久默认值）。

**卡片 C：号池监控**

- ☑ 启用监控；巡检间隔（分钟）；自动修复临时错误；修复失败上限；自动补号（开关+阈值输入）；补号暂停远端账号开关；分类正则高级折叠框（banned_patterns / rate_limit_patterns，textarea 一行一条）。
- 状态行：`上次巡检 xx 分钟前 · 下次 x 分钟后 · 上轮：扫描 n / 异常 n / 限流中 n / 在途修复 n / 废弃 n / 发起修复 n / 修复成功 n / 修复失败 n / 补号 n`；「立即巡检」按钮。
- 巡检日志：每轮折叠块 + 摘要 chip（状态量与动作量分列，chip 悬停有口径说明）；每账号明细行显示动作徽章，修复类明细带终态回执徽章（修复成功 / 修复失败 / 转待重授 / 已转完整登录），没有回执时写明本轮为何没发起修复（任务在途 / 冷却中 / 连败熔断 / 缺凭据 / 未开启自动修复）。

## 8. 设置 `/settings`

分区卡片：

- **安全**：修改密码（当前+新+确认）；「登出所有设备」；活跃会话列表（ip / 最近活跃 / 当前标记）。
- **邮箱取件**：Outlook 取件中转地址（默认 `https://8t92.cc/api/fetch-mails`）。
- **接码平台**：Tab（LubanSMS / SMSBower / 自定义号池）；SMSBower 支持「查询价格」拉取国家价格下拉（`POST /sms-providers/smsbower/options` 语义保留）；自定义号池 textarea（`+86xxx----API` 每行一条）；api_key 保存后显示掩码。
- **引擎参数**：最大并发任务数（默认 20）、任务超时分钟、代理失败阈值。

## 9. 概览 Dashboard `/`

- 顶部 4 张 StatCard：备用池可用 / 主池可用（副文本：总余额 $xx）/ 任务进行中（副文本：排队 x 待输入 y）/ 存活代理（副文本：共 x 条）。

  - 右：sub2api 监控状态卡（启停开关 + 上轮结果 + 立即巡检）。
- 底部：最近账号动态表（recent_events 15 条：时间 / 邮箱 / 事件中文 / 详情摘要），点击邮箱跳对应号池页。
- 30s 轮询。

## 10. 全局交互规范

- 所有变更操作成功 → sonner toast；失败 → toast(destructive) 显示 `error.message`。
- 危险操作（删除/废弃/取消全部）必须 ConfirmDialog。
- 异步受理（202）的操作：toast「已开始，稍后刷新」+ 相关列表 query 立即 invalidate。
- 空状态：每个表格有图标+文案+引导按钮（如备用池空 →「导入第一批邮箱」）。
- 加载态：表格 skeleton 行；按钮 busy 时 Spinner+禁用。
