# 02 数据库设计

数据库：**SQLite**，驱动 **better-sqlite3**（同步 API，单文件，配合 Docker volume 持久化）。

- 库文件：`data/tosub2.db`
- 打开参数：`{ journalMode: 'WAL', foreignKeys: 'ON', busyTimeout: 5000 }`
- 时间字段一律存 **ISO 8601 UTC 字符串**（`new Date().toISOString()`）
- 金额（余额）存 `REAL`（美元）
- 迁移机制：`server/lib/db.js` 启动时按 `PRAGMA user_version` 顺序执行 `server/migrations/000N_*.sql`，每个迁移包在事务里，成功后 `PRAGMA user_version = N`

## 1. 表总览（7 张）

| 表 | 用途 | 敏感字段 |
|---|---|---|
| `settings` | 系统配置（sub2api 配置、监控、Outlook 取件、接码平台、上传默认值…） | 部分值加密 |
| `proxies` | 代理列表与测活结果 | `url`（内含账号密码，加密存） |
| `accounts` | 三级号池统一账号表（`pool` 字段区分） | `credentials_enc` / `tokens_enc` 加密 |
| `account_events` | 账号流转审计（导入/移池/上传/废弃…） | 无 |
| `jobs` | 任务队列与状态机 | 无（凭据在 accounts 表） |
| `sessions` | 登录会话（token 哈希） | 无（只存哈希） |
| `login_attempts` | 登录失败计数（跨重启保持锁定） | 无 |

加密信封格式（详见 [07-安全设计.md](./07-安全设计.md)）：`v1:<base64(iv)>:<base64(tag)>:<base64(ciphertext)>`，算法 AES-256-GCM。

## 2. 建表 SQL（迁移 0001_init.sql 全文）

```sql
PRAGMA foreign_keys = ON;

-- ============ 系统配置 ============
-- key 约定（value 为 JSON 字符串；encrypted=1 时 value 为加密信封）：
--   sub2api.config      { base_url, admin_key, group_ids[], upload_defaults{...}, monitor{...} }
--   outlook.fetch       { endpoint }
--   sms.providers       { active: "luban|smsbower|custom", luban:{...}, smsbower:{...}, custom:{...} }
--   engine.config       { max_concurrent_jobs, proxy_fail_threshold }
--   console.password    { salt, hash }        (encrypted=1)
CREATE TABLE settings (
  key         TEXT PRIMARY KEY,
  value       TEXT NOT NULL,
  encrypted   INTEGER NOT NULL DEFAULT 0,
  updated_at  TEXT NOT NULL
);

-- ============ 代理列表 ============
-- url 存归一化后的完整代理 URL（可能含账号密码，加密存储）；
-- plain_url_hint 存脱敏展示串 http://user:***@host:port
CREATE TABLE proxies (
  id               INTEGER PRIMARY KEY AUTOINCREMENT,
  url_enc          TEXT NOT NULL,                    -- 加密信封
  url_hash         TEXT NOT NULL UNIQUE,             -- sha256(归一化url) 用于查重
  display_url      TEXT NOT NULL,                    -- 脱敏展示 http://user:***@host:port
  protocol         TEXT NOT NULL,                    -- http|https|socks5|socks5h
  label            TEXT,
  status           TEXT NOT NULL DEFAULT 'unknown'
                   CHECK (status IN ('unknown','alive','cf_challenge','dead','testing')),
  last_checked_at  TEXT,
  last_latency_ms  INTEGER,
  fail_count       INTEGER NOT NULL DEFAULT 0,       -- 任务中连接失败累计（成功一次清零）
  consecutive_dead INTEGER NOT NULL DEFAULT 0,       -- 测活连续失败次数
  last_error       TEXT,
  rotatable        INTEGER NOT NULL DEFAULT 0,       -- 是否支持会话轮换(用户名/密码含会话字段)
  created_at       TEXT NOT NULL,
  updated_at       TEXT NOT NULL
);
CREATE INDEX idx_proxies_status ON proxies(status);

-- ============ 账号（三级号池统一表） ============
-- pool 流转: reserve → main → discard（discard 可手动回 main）
-- status 按 pool 分组取值，见 04-04 号池模块状态机
CREATE TABLE accounts (
  id               INTEGER PRIMARY KEY AUTOINCREMENT,
  email            TEXT NOT NULL UNIQUE COLLATE NOCASE,
  pool             TEXT NOT NULL DEFAULT 'reserve'
                   CHECK (pool IN ('reserve','main','discard')),

  status           TEXT NOT NULL DEFAULT 'mail_pending',
  note             TEXT,

  -- 登录凭据（加密 blob, JSON 见下方字段说明）
  credentials_enc  TEXT,

  -- ---- reserve 专属 ----
  initial_balance  REAL,                             -- 邮件初始化的初始余额(美元)
  has_balance      INTEGER NOT NULL DEFAULT 0,
  banned           INTEGER NOT NULL DEFAULT 0,       -- 邮件命中封禁关键字
  banned_reason    TEXT,
  mail_status      TEXT CHECK (mail_status IN ('pending','checking','ok','fetch_failed')),
  mail_error       TEXT,
  imported_at      TEXT,
  last_checked_at  TEXT,                             -- 最近一次邮件检查时间

  -- ---- main 专属 ----
  tokens_enc       TEXT,                             -- 加密 blob: OAuth tokens, JSON 见下方
  balance          REAL,                             -- 实时余额(美元, backend-api/wham/usage)
  balance_checked_at TEXT,
  balance_error    TEXT,
  last_login_at    TEXT,
  sub2api_account_id INTEGER,                        -- sub2api 侧账号 id（上传后回填）
  sub2api_uploaded_at TEXT,
  auto_repair_blocked INTEGER NOT NULL DEFAULT 0,    -- 永久失败标记，监控跳过
  last_auto_repair_at  TEXT,

  -- ---- discard 专属 ----
  discard_reason   TEXT CHECK (discard_reason IN
                     ('banned_401','rate_limited_429','repair_failed','login_failed','manual')),
  discard_detail   TEXT,                             -- 原始错误信息(截断至 2000 字符)
  discarded_at     TEXT,

  created_at       TEXT NOT NULL,
  updated_at       TEXT NOT NULL
);
CREATE INDEX idx_accounts_pool_status ON accounts(pool, status);
CREATE INDEX idx_accounts_balance ON accounts(pool, balance) WHERE pool = 'main';

-- ============ 账号流转审计 ============
-- type 取值: imported / mail_checked / join_started / join_failed / join_succeeded /
--            login_succeeded / login_failed / balance_refreshed / uploaded_sub2api /
--            sub2api_replaced / sub2api_linked / sub2api_unlinked / sub2api_duplicate /
--            auto_repair_started / repair_parked / moved_to_discard / restored / note_changed / deleted
CREATE TABLE account_events (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  account_id  INTEGER NOT NULL REFERENCES accounts(id) ON DELETE CASCADE,
  type        TEXT NOT NULL,
  detail      TEXT,                                  -- JSON: { reason, balance, job_id, ... }
  created_at  TEXT NOT NULL
);
CREATE INDEX idx_account_events_account ON account_events(account_id, created_at DESC);
CREATE INDEX idx_account_events_time ON account_events(created_at DESC);

-- ============ 任务 ============
-- status: queued → running → awaiting_input → running → … → completed|failed|canceled
-- type:   login（完整登录/重登）| refresh（refresh_token 换新）| balance（查余额）
--         | totp_setup（设置 2FA）
CREATE TABLE jobs (
  id               TEXT PRIMARY KEY,                 -- uuid v4
  account_id       INTEGER REFERENCES accounts(id) ON DELETE SET NULL,
  type             TEXT NOT NULL CHECK (type IN ('login','refresh','balance','totp_setup')),
  status           TEXT NOT NULL DEFAULT 'queued'
                   CHECK (status IN ('queued','running','awaiting_input','completed','failed','canceled')),
  stage            TEXT,                             -- 当前阶段: 见 04-06 状态机
  prompt_kind      TEXT,                             -- awaiting_input 时等待的输入类型
  attempt          INTEGER NOT NULL DEFAULT 1,       -- 含代理风控重启在内的总尝试次数
  proxy_id         INTEGER REFERENCES proxies(id),   -- 随机选中的代理（可空=本机直连）
  proxy_attempts   INTEGER NOT NULL DEFAULT 0,       -- 已消耗的代理会话数
  log_path         TEXT NOT NULL,                    -- data/logs/<id>.log
  result_path      TEXT,                             -- data/results/<id>.json（login 产物）
  checkpoint_path  TEXT,                             -- data/checkpoints/<account_id>/login.json
  totp_result_path TEXT,
  error            TEXT,
  resume_job_id    TEXT,                             -- 批量授权时由哪个旧 job 派生（审计用）
  created_at       TEXT NOT NULL,
  started_at       TEXT,
  finished_at      TEXT,
  updated_at       TEXT NOT NULL
);
CREATE INDEX idx_jobs_status ON jobs(status, created_at);
CREATE INDEX idx_jobs_account ON jobs(account_id, created_at DESC);
-- 同一账号同时最多一个活跃任务（邮箱级互斥的 DB 兜底）
CREATE UNIQUE INDEX idx_jobs_active_per_account
  ON jobs(account_id) WHERE status IN ('queued','running','awaiting_input')
  AND account_id IS NOT NULL;

-- ============ 登录会话 ============
CREATE TABLE sessions (
  token_hash   TEXT PRIMARY KEY,                     -- sha256(原始token) hex
  created_at   TEXT NOT NULL,
  expires_at   TEXT NOT NULL,
  last_seen_at TEXT NOT NULL,
  ip           TEXT,
  user_agent   TEXT
);
CREATE INDEX idx_sessions_expires ON sessions(expires_at);

-- ============ 登录失败计数（按 IP） ============
CREATE TABLE login_attempts (
  ip           TEXT PRIMARY KEY,
  fail_count   INTEGER NOT NULL DEFAULT 0,
  locked_until TEXT,                                 -- ISO 时间；空=未锁
  updated_at   TEXT NOT NULL
);
```

## 3. 加密 blob 的明文结构

### 3.1 `accounts.credentials_enc`（解密后 JSON）

```jsonc
{
  "password": "ChatGPT 登录密码",           // 可空
  "totp_secret": "JBSWY3DPEHPK3PXP",       // 可空，Base32
  "mail_api_url": "https://mail.example/messages/token", // 可空，泛化收码 API
  "phone": "+8613711111111",               // 可空，已绑定的手机号
  "outlook": {                              // 备用池导入的 Outlook 凭据
    "password": "邮箱密码",
    "client_id": "9e5f94bc-e8a4-4e73-b8be-63364c29d753",
    "refresh_token": "M.C509_BL2..."
  },
  "proxy_url": "http://user:pass@host:port" // 可空，账号级固定代理（v1 兼容字段）
}
```

### 3.2 `accounts.tokens_enc`（解密后 JSON，主号池）

```jsonc
{
  "access_token": "eyJhbGciOi...",
  "refresh_token": "rt_...",
  "id_token": "eyJhbGciOi...",
  "chatgpt_account_id": "us_xxx",
  "chatgpt_user_id": "user_xxx",
  "client_id": "app_EMoamEEZ73f0CkXaXp7hrann",
  "email": "a@b.com",
  "obtained_at": "2026-08-15T00:00:00.000Z"
}
```

### 3.3 `settings` 中 `sub2api.config`（值整体加密）

```jsonc
{
  "base_url": "http://127.0.0.1:8080",
  "admin_key": "sk-xxxx",
  "group_ids": [1, 3],                      // 空数组=不指定分组
  "upload_defaults": {
    "concurrency": 10,                      // 可空=保留账号原值
    "load_factor": 1,
    "priority": 1,
    "model_whitelist": ["gpt-5", "gpt-5-mini"],
    "disable_auto_pause_5h": false,
    "disable_auto_pause_7d": false,
    "auto_select_proxy": true,              // 自动绑定 sub2api 内绑定数最少的代理
    "proxy_id": null                        // 手动指定代理 id；非空时 auto_select_proxy 失效
  },
  "monitor": {
    "enabled": true,
    "interval_minutes": 5,                  // 巡检间隔
    "cooldown_minutes": 5,                  // 自动修复冷却
    "auto_repair": true,                    // 临时错误自动重登修复
    "max_repair_attempts": 2,               // 修复失败 N 次后移入废弃池
    "auto_replenish": false,                // 主池低于阈值自动从备用池补号
    "reserve_threshold": 10,                // 本地主池可用数下限（远端非 error/非限流 + 在途 joining）
    "banned_patterns": ["account_deactivated", "deactivated", "suspended",
                        "banned", "permanently deleted", "401"],
    "rate_limit_patterns": ["429", "rate limit", "too many requests"]
  }
}
```

> 分类正则存在配置里而非硬编码：sub2api 版本间错误文案字段可能不同，用户可按实测调整（详见 [04-后端设计/05-sub2api模块.md](./04-后端设计/05-sub2api模块.md)）。

## 4. 关键约束与事务边界

### 4.1 池流转的原子性

所有 `pool` 变更必须在**单事务**内完成「改 accounts + 写 account_events」，避免半状态：

```
reserve → main : UPDATE accounts SET pool='main', status='active', tokens_enc=?, ...
                last_login_at=?, balance=?, balance_checked_at=? WHERE id=?
                + 清空 reserve 快照字段(按需保留 initial_balance 供展示)
                + INSERT account_events(type='join_succeeded')
main → discard : UPDATE accounts SET pool='discard', discard_reason=?, discard_detail=?,
                discarded_at=? WHERE id=? AND pool='main'
                + INSERT account_events(type='moved_to_discard')
discard → main: UPDATE accounts SET pool='main', status='needs_reauth', discard_reason=NULL
                WHERE id=? AND pool='discard'
                + INSERT account_events(type='restored')
```

`WHERE pool='...'` 条件保证并发下不会重复流转（乐观锁语义，受影响行数=0 则报冲突）。

### 4.2 任务与账号的状态互斥

- `idx_jobs_active_per_account` 唯一部分索引在 DB 层保证同一账号只有一个活跃任务。
- 业务层先 `UPDATE accounts SET status='authorizing' WHERE id=? AND status IN (允许的前置状态)`，受影响行数=0 说明被并发占用，直接拒绝。
- 创建任务与置账号状态在**同一事务**。

### 4.3 settings 读写

- 读：启动时整表载入内存缓存，`UPDATE` 后刷新缓存（单进程，无失效问题）。
- 写：`INSERT INTO settings(key,value,encrypted,updated_at) VALUES(...) ON CONFLICT(key) DO UPDATE SET ...`。

## 5. 数据生命周期

| 数据 | 保留策略 |
|---|---|
| `jobs` 行 | **全量保留**（不自动清理）；用户在任务中心手动清理 N 天前结束的终态任务（`POST /jobs/cleanup`，`DELETE WHERE status IN ('completed','failed','canceled') AND COALESCE(finished_at, updated_at, created_at) < now-Nd`） |
| `data/logs/*.log` | 随 job 行删除时一并删除 |
| `data/results/*.json` | **不自动删**（token 产物，账号在主池期间可能复用）；账号删除时一并删 |
| `data/checkpoints/<accountId>/` | 账号删除时删；登录最终成功后删（token 已入 tokens_enc） |
| `account_events` | 永久保留（量级小：每账号几十条） |
| `sessions` | 每次校验时懒删除过期行；登录时顺带清理 |
| `login_attempts` | 锁定过期后计数清零 |

## 6. 迁移文件规划

```
server/migrations/
├── 0001_init.sql        # 上文全部建表
├── 0002_seed.sql        # 无（种子数据由代码写入 settings 默认值，不放 SQL）
└── 000N_*.sql           # 后续演进：只增不改；改列用 ALTER TABLE，废弃列保留不删
```

迁移执行器伪代码（`server/lib/db.js`）：

```js
export function openDatabase(dataDir) {
  const db = new Database(join(dataDir, 'tosub2.db'));
  db.pragma('journal_mode = WAL');
  db.pragma('foreign_keys = ON');
  db.pragma('busy_timeout = 5000');
  const current = db.pragma('user_version', { simple: true });
  for (const m of migrations /* 按文件名排序解析出序号与 SQL */) {
    if (m.version <= current) continue;
    db.exec('BEGIN');
    try {
      db.exec(m.sql);
      db.exec(`PRAGMA user_version = ${m.version}`);   // 注意: pragma 需在事务外也可,此处放事务内 better-sqlite3 支持
      db.exec('COMMIT');
    } catch (e) { db.exec('ROLLBACK'); throw e; }
  }
  return db;
}
```

## 7. 备份

- 停机备份：`docker compose stop` 后直接打包 `data/` 目录。
- 在线备份：`scripts/backup.mjs` 使用 better-sqlite3 的 `db.backup(destPath)`（内部走 SQLite backup API，WAL 下安全），再连同 `data/checkpoints/`、`data/results/` 一起打包。
- 恢复：停服务 → 覆盖 `data/` → 启动（迁移器自动补齐落后版本的 schema）。
